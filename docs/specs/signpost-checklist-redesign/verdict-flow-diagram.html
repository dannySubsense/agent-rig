Gate & evaluation flow

Corrected 2026-09-07 after a Cold Frank opinion pass (not a gate) found the first draft's topology wrong: it drew the unmatched-row check (Rule 7) as an independent sweep running in parallel with the per-line matching loop. The spec says otherwise — 04-ROADMAP.md Slice 3 is explicit that Rule 7 is computed "by iterating pillar_rows after the per-Signpost-line matching pass" — a residue pass over whatever the loop didn't consume, not a parallel check. That correction also surfaced a real, undecided spec ambiguity: Rule 5 flags whichever verified row claiming a reused ID comes "later," but with Rule 7 running strictly after the main loop, an unmatched row that appears above a matched row sharing its ID is evaluated after it — the spec never says whether "earlier" means source order or evaluation order. Flagged below at the node where it bites, not resolved here.
