- **Governance Doc Audit — Cataloging Rules for Hook vs. Doctrine Disposition** — surfaced 2026-09-06 (Danny). Decision: CLAUDE.md (and other governance markdowns — CADENCE.md, INVARIANTS.md, DDR-DEFINITION.md, across projects) are never "closed" once a rule is written into them. Agents keep stuffing new rules into them as a catch-all and treating the write as resolution; agents also lose sight of important rules once buried in a bloated markdown, and agents inconsistently apply markdown rules as live checks on their own behavior versus reciting them after the fact. Corrective decided: periodically audit these governance docs — catalog every rule, and for each, determine (a) whether it's mechanically checkable (inspectable from a dispatch/action's structure, not requiring semantic judgment), (b) whether it has actually been followed in a recent real audit (not just asserted), (c) disposition: build as a hook, remain doctrine only, or needs periodic re-audit rather than one-time authorship. Cold-Gate (the "two mandatory requirements, not one" rule already in `~/.claude/CLAUDE.md` — unbriefed dispatch + isolated detached checkout for any binding judgment gate like Frank) is confirmed, in this session, as a strong hook candidate: its violation condition is structurally inspectable (prompt content, checkout path) rather than requiring semantic understanding, unlike most CLAUDE.md doctrine. Additional items surfaced via Switchboard relay messages from other agents (ledger/department-os, vane/signal-current) this same day, to be triaged in the follow-up session: (1) Cold-review cadence gap — a correctly-unbriefed Frank dispatch can still be "Warmed-up Frank" if run against one narrow, freshly-authored commit instead of the whole accumulated state — the orchestrator's own commit sequencing pre-shapes what's "in view" independent of prompt wording; not covered by the existing Cold Gates rule. (2) Orchestrator must independently re-verify any repo-state fact a Frank finding asserts (e.g. "this directory doesn't exist") before fixing on its basis, rather than adopting the finding's factual claim uncritically — extends doer≠checker to cover a checker's factual claims, not just its judgment calls. (3) "Speed kills" — no fix dispatch should hand a fixer a bare keyword/pattern/line-number list as the sweep definition; it should instruct a full end-to-end read of the relevant section(s), with the named defect as an orienting example only. Flagged by its author as a strong hook candidate too (mechanically detectable: a dispatch prompt containing a bare list of file:line tokens with no "read the full section" instruction). Corrective: pass verdicts and fix instructions from Cold Frank and Sol to downstream sub-agents verbatim, never paraphrased or summarized. CLAUDE.md rule 1 already states this narrowly for benchmark dispatches ("hand it the actual finding/verdict text verbatim rather than a paraphrase") — this generalizes that same principle to every verdict-to-fix-dispatch handoff, not just benchmark. (6) Cold Frank refusal at the agent-definition level: Danny has had to personally correct five different orchestrators this week on the definition and correct dispatching of Cold Frank (versus Warmed-up Frank). The corrective needs to go further than an orchestrator-side dispatch-shape check (item (1)/Cold-Gate above) — Frank's own agent definition (`agents/frank.md`) should be written to actively refuse a "warmed" dispatch itself: if Frank is handed a file list, a scope narration, prior-verdict content, or any other briefing beyond repo+SHA+verdict-required, Frank's own instructions should have Frank detect this and refuse/flag the dispatch as non-compliant, rather than silently complying and producing a verdict anyway.
